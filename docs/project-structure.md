# Project Structure

## Directory Tree

```
root/
  frontend/
    src/
      components/
        Layout/        ← Layout, Navbar, Sidebar, Footer
        ui/            ← Button, Input, Modal, Spinner, Badge
      pages/           ← Route-level page components
      hooks/           ← Custom React hooks
      services/        ← API service layer (axios)
      store/           ← Redux store, slices, hooks
      utils/           ← dateUtils, stringUtils, validationUtils
      test/            ← React Testing Library + Vitest tests
  backend/
    logs/              ← Auto-created at runtime; in .gitignore
    src/
      controllers/     ← Thin request/response handlers
      services/        ← All business logic and DB queries
      routes/          ← Express route definitions
      db/
        schema/        ← Drizzle table definitions (one file per domain)
        migrations/    ← Auto-generated by drizzle-kit
        seed/          ← Seed scripts
        index.js       ← Drizzle client export (pool + db instance)
      validators/      ← All Zod schemas (one file per domain)
      middleware/      ← errorHandler, asyncHandler, authMiddleware,
                          requestLogger, validateRequest
      config/          ← logger config (winston)
      utils/           ← successResponse, errorResponse, asyncWrapper
      test/            ← Jest tests
  docs/
  .github/
    workflows/         ← ci.yml + cd.yml
```

## Key Directories

### `backend/logs/`
Auto-created at server startup by the Winston logger config. Not committed to git (in `.gitignore`).
Contains `combined.log` (all levels) and `error.log` (errors only).

### `backend/src/utils/`
Contains `successResponse.js` and `errorResponse.js`. Every API response MUST use these — never construct `{ success, data, error }` manually.

### `backend/src/validators/`
ALL Zod schemas live here. One file per domain. Never define schemas in controllers, routes, or middleware.

### `backend/src/db/`
Drizzle ORM setup. `index.js` exports `{ db, pool }`. Schema files define tables. Migrations are auto-generated by `drizzle-kit`.

### `frontend/src/components/Layout/`
Shared layout components wrapping every page via React Router's `<Outlet />`. Never wrap individual pages with Navbar/Footer.

### `frontend/src/components/ui/`
Purely presentational, props-driven UI primitives. Always use these instead of raw HTML elements with inline styles.

### `frontend/src/test/`
Vitest + React Testing Library tests. Covers auth and UI component failure cases.
